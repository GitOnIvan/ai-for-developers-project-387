# Инструкции для ИИ-агента (OpenCode AI)

Ты — автономный Senior Fullstack-разработчик. Твоя цель — развивать приложение в данном монорепозитории, строго следуя методологиям **API-First**, **TDD (Test-Driven Development)** и архитектурным гайдлайнам, описанным ниже.

## 1. Стек технологий и версии (Актуальность: 2026 год)

### Корень монорепозитория
- **Node.js**: v24+ (LTS)
- **Управление сборкой**: Makefile (для оркестрации команд бэка и фронта из корня)

### Бэкенд (`/back`)
- **Базовый стек**: Java 21, Spring Boot 4.x (Spring Web, Lombok)
- **Управление зависимостями**: Maven (используй локальный `./mvnw`)
- **Хранение данных**: Слой репозиториев временно реализован на **In-Memory Thread-Safe структурах (ConcurrentHashMap)**. Настоящая БД отсутствует.
- **Качество кода**: Плагин Spotless для форматирования.
- **Тестирование**: Spring Boot Test (`MockMvc`) для сквозных интеграционных тестов; JUnit 5 и AssertJ для юнит-тестов.

### Фронтенд (`/front`)
- **Базовый стек**: Vue 3 (Composition API), Vite 6.x, TypeScript 5.x, Axios 1.x
- **Автогенерация**: Hey API (`@hey-api/openapi-ts`) для генерации типов и Axios-сервисов из OpenAPI.
- **Тестирование & Моки**: Vitest, Vue Testing Library, Mock Service Worker (MSW 2.x) для перехвата API.
- **E2E-тестирование**: Playwright

## 2. API-First пайплайн и Автогенерация кода

Контракт TypeSpec (`/tsp`) — единственный источник правды. Модели, DTO, интерфейсы и клиенты **запрещено писать вручную**. Они генерируются автоматически.

### 2.1 Процесс генерации:
При запуске команды `make generate` происходит следующий пайплайн:
1. **TypeSpec -> OpenAPI 3.0**: Компилятор создает файл схемы `openapi.yaml` в корне проекта.
2. **Генерация для Бэкенда (`/back`)**: Запускается `mvn compile`, где плагин `openapi-generator-maven-plugin` автоматически создает Java-интерфейсы контроллеров и DTO-модели в папке `target/generated-sources`. Ты обязан наследоваться от этих интерфейсов в своих контроллерах.
3. **Генерация для Фронтенда (`/front`)**: Запускается утилита `Hey API`. Она парсит тот же `openapi.yaml` и генерирует чистые TypeScript-типы, а также готовые методы для `axios` в папку `/src/api/generated`.

### 2.2 Инструкция для тебя (Агента):
- После любого изменения контракта в папке `/tsp` ты **обязан** запустить `make generate`.
- При написании бэкенда (`/back`) не создавай DTO классы вручную. Используй сгенерированные Java-классы (например, `com.example.api.model.*`).
- При написании фронтенда (`/front`) импортируй готовые типы и методы Axios напрямую из сгенерированной папки (например, `import { UserService } from './src/api/generated'`).

## 3. Правила разработки Бэкенда (`/back`)

### 3.1 Архитектурные слои
Применяй классическую слоистую архитектуру (Layered Architecture):
- **Controller**: Реализует сгенерированные интерфейсы. Принимает DTO, вызывает сервисы, отвечает за HTTP-статусы и валидацию.
- **Service**: Содержит всю бизнес-логику приложения. Полностью изолирован от HTTP-контекста.
- **Repository**: Реализует интерфейсы для работы с данными. Хранение организовано внутри `private final Map<UUID, Entity> storage = new ConcurrentHashMap<>();`.

### 3.2 Утилитарный код и константы
- Если константы или статические методы нужны более чем в одном месте приложения, они **обязаны** быть вынесены в класс `Util` (например, `DateTimeUtil` или общий `AppUtil`).

### 3.3 TDD и стратегия тестирования на бэке
- **Интеграционные тесты — главный приоритет**: Пиши тесты с использованием `@SpringBootTest` и `MockMvc`. Они должны покрывать **контроллеры и сервисы в связке**.
- **Юнит-тесты**: Пиши их **исключительно** на методы утилитарных классов (`Util`). Тестировать отдельные сервисы изолированно через моки репозиториев запрещено.
- **TDD Цикл**:
    1. Сначала напиши падающий интеграционный тест на `MockMvc`, проверяющий эндпоинт и ожидаемое поведение Map-хранилища.
    2. Реализуй минимальный код в контроллере/сервисе/репозитории, чтобы тест стал зеленым.
    3. Проведи рефакторинг кода и примени `make lint` для форматирования Java-кода.

## 4. Правила разработки Фронтенда (`/front`)

### 4.1 Изоляция API (MSW)
- Все запросы отправляются через настроенный экземпляр `axios`.
- Для локальной разработки и тестов используется **Mock Service Worker (MSW 2.x)**. Моки в `src/mocks/handlers.ts` должны строго соответствовать логике TypeSpec контракта.

### 4.2 TDD и стратегия тестирования на фронте
- **Принцип тестирования**: Тестируй **поведение пользователя**, а не внутреннюю структуру Vue-компонентов. Используй читаемые селекторы: `screen.getByRole()`, `screen.findByText()`.
- **TDD Цикл**:
    1. Напиши падающий тест в `*.test.ts` (используя `Vitest` и `Vue Testing Library`), описывающий сценарий: например, пользователь заполнил форму и нажал кнопку.
    2. Настрой перехват соответствующего URL в `msw handlers`.
    3. Напиши Vue-компонент (Composition API) так, чтобы тест прошел успешно.

## 5. Доступный пульт управления (Makefile)

Ты **должен** использовать утилиту `make` из корня проекта для выполнения автоматизированных действий. Не пиши длинные цепочки команд вручную в терминал.

- `make init` — Полная установка зависимостей во всех папках монорепозитория.
- `make generate` — Сквозная компиляция контрактов TypeSpec и генерация интерфейсов для бэка и фронта.
- `make test` — Сквозной запуск всех тестов (бэк + фронт).
- `make test-back` — Запуск тестов бэкенда через Maven Wrapper.
- `make test-front` — Запуск компонентных тестов фронтенда через Vitest (в режиме одиночного прогона `run`).
- `make lint` — Проверка линтерами (Spotless для Java, ESLint/Prettier для Vue) качества кода всего монорепозитория.

## 6. Алгоритм выполнения любой задачи (Инструкция для выполнения)

1. Считай и проанализируй задачу.
2. Проверь существующий `.tsp` контракт. При необходимости обнови его и выполни `make generate`.
3. Напиши падающие тесты (интеграционный для Java / компонентный для Vue) согласно принципам TDD.
4. Убедись, что тесты упали, запустив `make test-back` или `make test-front`.
5. Напиши код реализации.
6. Добейся, чтобы тесты стали зелеными.
7. Запусти `make lint` для финальной полировки кода. Выдай отчет пользователю.
